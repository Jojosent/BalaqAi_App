# BalaqAi

Expo SDK 58 / React Native / TypeScript + Node.js + Firebase (`balaqaidb`). Интерфейс собран по предоставленным макетам.

## Веб-версия на Vercel

Публичная ссылка для телефона и компьютера: **https://balaqai-app-five.vercel.app**.

Корень репозитория настроен как Vercel-проект `balaqai-app`. Команда `npm run build` устанавливает зависимости Expo из lock-файла и создаёт `mobile/dist-web`. `vercel.json` отдаёт SPA и поддерживает обновление страницы на внутренних маршрутах. Проект связан с GitHub для автоматического деплоя ветки main.

В браузере используется `mobile/src/services/api.web.ts`: Firebase Auth + прямой доступ к Firestore. **Серверный ключ в Vercel не передаётся** и не требуется. Опубликованные `firestore.rules` разрешают чтение и запись только вошедшему владельцу документа `users/{uid}`, проверяют структуру данных и запрещают просмотр списка пользователей. Правила применяются локально через `cd server; node --env-file=.env deploy-rules.mjs`. Синтетический live-тест правил: `node --env-file=.env test-web-rules.mjs` (требуется публичный `FIREBASE_WEB_API_KEY`).

Для Google OAuth точный публичный домен Vercel должен быть в Firebase Authorized domains. Apple пока не настроен. Для будущей нативной версии остаётся Node.js API, описанный ниже; веб-сайт от него не зависит.

## Запуск

Node.js 24.11+; после клонирования используйте `npm ci` в `mobile` и `server` (lock-файлы фиксируют совместимые версии Firebase).

Терминал 1:

```powershell
cd server
# Если .env отсутствует, скопируйте .env.example и задайте путь к серверному ключу.
npm start
```

Терминал 2:

```powershell
cd mobile
# Локальная .env уже содержит адрес API и существующий Google Web client ID.
npm run web
```

Браузер: http://localhost:8081. API по умолчанию слушает только `127.0.0.1:3001`. Для телефона задайте `HOST=0.0.0.0` в серверной .env, `EXPO_PUBLIC_API_URL=http://LAN-IP-КОМПЬЮТЕРА:3001` в mobile/.env и перезапустите процессы. Для Android-эмулятора адрес компьютера обычно `http://10.0.2.2:3001`. Для публикации необходим HTTPS-сервер и его URL; локальный Node-процесс не является облачным деплоем.

## Авторизация и хранение

- `/register`: email, пароль от 8 символов, повтор пароля. Firebase создаёт аккаунт и сразу выполняет вход без письма подтверждения.
- `/login`: email и пароль. `/reset-password` отправляет письмо для восстановления через Firebase.
- `/verify`: устаревшая ссылка автоматически переводит вошедшего пользователя к следующему шагу анкеты.
- Для доступа к профилю нужен действующий Firebase ID token; подтверждение email не требуется. Сессия восстанавливается Firebase SDK: Web persistence в браузере, AsyncStorage на устройствах.
- Новый пользователь проходит анкету, выбор этапа и расчёт срока. После повторного входа данные загружаются из Firestore; завершённая анкета ведёт на главную.
- В Firestore по адресу `users/{firebaseUid}` сохраняются имя, дата рождения, город, этап, дата начала беременности, врач/заметки, чек-лист и включённое отслеживание. Пароли и токены сервер в документах не хранит.
- Изменения отправляются последовательно с задержкой 450 мс. Ошибка сохранения видна в баннере с повтором. Перед выходом незавершённое сохранение ожидается; кнопка выхода находится внизу профиля.
- Пока приложение закрыто без соединения до успешного сохранения, несохранённые изменения могут быть потеряны. Полноценный offline-режим пока не реализован.

Нативный API: `GET /health`, `GET /v1/me`, `PUT /v1/me`. Доступ к `/v1/me` только с `Authorization: Bearer <Firebase ID token>`. Сервер проверяет подпись, срок действия и отзыв токена, берёт UID из токена и валидирует тело запроса. CORS разрешает только `ALLOWED_ORIGINS`. В веб-версии те же документы защищены Firestore rules и читаются напрямую SDK. Admin SDK используется только локальным Node.js-сервером и локальными проверками. Файл ключа и `.env` исключены из Git и загрузки Vercel, в Expo попадает только публичный Web config.

## Google и Apple

Реальные интеграции заменили вымышленные аккаунты и согласия. Подробности и оставшиеся настройки: [FIREBASE_SETUP.md](FIREBASE_SETUP.md).

Google уже включён в Firebase. В браузере используется официальный Firebase popup, localhost уже разрешён. На Android/iOS используется Google Sign-In SDK, которому ещё нужны зарегистрированные приложения, SHA-отпечатки Android, iOS client ID и development build. Expo Go нативный Google Sign-In не содержит.

Apple: Web Firebase OAuth и native iOS Sign in with Apple с nonce подготовлены. Провайдер Apple в проекте пока отсутствует; владелец сообщил, что Apple Developer Account нет. До его оформления и настройки Apple-вход не работает. На Android нативный Apple-вход в этой реализации не поддерживается — доступны email и Google.

## Экраны

Главная — `/home`, профиль — `/account`, сообщество — `/community`, магазин — `/shop`. Из главной и профиля «Толығырақ» открывает `/tracker`. До 20 завершённых недель используется луна, с 20 — `baby2.png`; просмотр других недель не меняет сохранённый срок.

Расчёт беременности: дата последних месячных +280 дней; известный срок переводится в исходную дату. Это ориентировочная оценка, уточняемая врачом/УЗИ. [ACOG](https://www.acog.org/clinical/clinical-guidance/committee-opinion/articles/2017/05/methods-for-estimating-the-due-date). Планирование открывает список обследований; беременность — главную с карточками и трекером.

Сообщество использует две ознакомительные публикации с фото из предоставленного макета. Реакции, подписки и сохранённое хранятся в личных настройках Firebase; комментарии настоящие и видны вошедшим пользователям. Автор может удалить свой комментарий. Статистика продаж, просмотров и реакций из макета не выдаётся за реальные данные.

Магазин — каталог видов товаров по четырём категориям с избранным в аккаунте и внешним поиском продавцов. Изображения обозначают категории, а не конкретные предложения. Оплата, заказы, цены и скидки не подключены по просьбе владельца.

Новые экраны: /connect (приглашения и доступ близких), /reminders (напоминания внутри приложения), /features (бесплатные возможности), /privacy (копирование личных данных и управление доступом), /help (FAQ). Фоновые push-уведомления не реализованы.

```powershell
cd mobile

npm run test:pregnancy

```

```powershell
cd server
npm test

$env:FIREBASE_WEB_API_KEY='публичный-apiKey-из-firebaseConfig'
```

Unit-тест API проверяет отказы без токена, неверный токен, вход без подтверждения email, ограничения полей/размера/JSON, CORS и изоляцию пользователей. Live-тест использует реальный Firebase email/password, проверяет вход без подтверждения email, чтение/запись Firestore и изоляцию UID. Вход в личные Google/Apple аккаунты должен проверить владелец.


## Личные дневники и задачи

Веб- и мобильный клиент хранят сеансы движений в `users/{uid}/kickSessions/{startedAt}`, измерения веса — в `users/{uid}/weightEntries/{at}`, настройки веса — в `users/{uid}/tracking/weight`, свои задачи по разделам — в `users/{uid}/customTasks/{group}`. Каждая запись проверяется отдельно, чтобы не превышать лимит вычислений Firestore Rules. Старые задачи из анкеты копируются в новый формат до следующего сохранения. Клиент показывает последние 20 сеансов движений и 30 измерений веса; старые записи в базе не удаляются. Напоминание о весе показывается на странице, push-уведомления не подключены.

Дневник настроения: `users/{uid}/moodEntries/{at}`. Запись содержит время и один из 18 вариантов; чтение и запись доступны только владельцу. На странице показаны последние 50 записей, старые записи в базе не удаляются.

## Языки и совместный доступ

По умолчанию используется казахский (kk), доступны русский (ru) и английский (en). Выбор находится непосредственно в профиле и в настройках, сохраняется локально отдельно для каждого аккаунта и в users/{uid}/settings/preferences. Словарь src/i18n/catalog.json содержит исходный казахский, русский, английский и при необходимости прежний вариант строки. Localized-компоненты переводят интерфейс, placeholder и подписи доступности; пользовательский контент отмечен verbatim. Названия YouTube-роликов из первоисточника остаются оригинальными. Тест i18n.test.mjs проверяет покрытие всех кириллических литералов и шаблонов.

QR-приглашение создаётся только нажатием пользователя после выбора данных. Случайный 192-битный код ведёт на публичный /connect?invite=…; ссылка сохраняется при входе. Для просмотра обновлений получатель входит в аккаунт и принимает приглашение. Метаданные shareInvites не содержат анкету, отдельный shareData читают только владелец и действующие участники. Ссылка действует шесть дней; новый код прекращает предыдущий доступ. Отдельного участника можно отключить без возможности самостоятельно вернуть доступ. Могут передаваться только имя, дата для расчёта срока и число выполненных задач, согласно выбранным разрешениям. Записки, email, дата рождения, вес и настроение не передаются. Для другого домена задайте EXPO_PUBLIC_WEB_URL.

Проверки новых функций:

~~~powershell
node --test mobile/scripts/i18n.test.mjs
# Правила тестируются на demo-проекте, без production данных:
npx firebase-tools emulators:exec --only firestore --project demo-balaqai --config firebase.test.json "node server/test-sharing-rules.mjs"
~~~
